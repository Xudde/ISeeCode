源码自动化审计平台 MVP 开发文档（AI IDE 分阶段投喂版）
 
文档说明
 
本文档面向 Trae Code / Cursor 等 AI 代码编辑器，采用分阶段交付、逐阶段验证的开发模式。每次仅向AI投喂单个阶段的需求，待代码生成、本地运行验证通过后，再投喂下一阶段，避免一次性生成全量代码导致结构混乱、依赖冲突、无法运行。
 
 
 
一、通用使用流程
 
1. 新建空项目目录，先投喂「总纲 + 阶段 0」内容，完成项目骨架搭建。
2. 单个阶段代码生成后，在 Ubuntu 22.04 虚拟机环境中执行启动测试。
3. 运行报错时，将完整 traceback 日志反馈给AI修复，直至通过验收标准。
4. 上一阶段验收通过后，再投喂下一阶段完整需求。
5. 禁止AI超前实现未到阶段的功能。
 
 
 
二、总体技术约束（所有阶段强制遵守）
 
类别 选型 说明 
开发语言 Python 3.10+ 全量类型提示，关键函数带 docstring 
Web框架 FastAPI + Uvicorn 异步入口，内置生命周期钩子

POC发包 httpx 高性能HTTP客户端 
运行环境 Ubuntu 22.04 + Docker 已预装 所有依赖可通过pip一键安装 
 
全局安全红线（硬编码实现，禁止仅注释说明）
 
1. 上传文件仅接受  .zip  格式，单文件 > 200MB 直接拒绝；解压后总大小 > 1GB 终止任务。
2. Zip Slip 防护：解压前逐条校验文件路径，包含  ..  或  /  开头的绝对路径，直接拒绝整个任务。
3. 恶意样本初筛：解压后扫描顶层可执行文件（.exe/.dll）、脚本中出现  curl|bash|wget  等特征，命中则标记任务失败，不进入扫描环节。
4. LLM API Key 仅存储于后端数据库，前端接口返回时脱敏展示为  sk-***xxxx 。
5. Docker沙箱强制约束：禁止privileged模式、禁止host网络；默认限制  --memory=512m --cpus=1 --pids-limit=128 ；任务超时5分钟强制销毁容器。
6. 任务执行全链路  try/except  包裹，任何异常不得导致worker线程退出。

八、排坑与调试指南
 
1. LLM JSON解析：必须实现 extract_json() 兜底函数，优先匹配`json代码块，再做贪婪正则匹配，最后 json.loads 异常捕获，避免LLM输出额外文本导致解析失败。
2. Semgrep规则：阶段1优先使用内置固定规则，不依赖 --config auto 联网模式，保证稳定性。
3. Docker环境：运行前确认当前用户在docker组，避免权限报错；容器构建产生的root文件，清理时使用 shutil.rmtree(ignore_errors=True) 。
4. 沙箱网络：第一版不做复杂iptables隔离，优先保证连通性；后续迭代再增加出站白名单控制。
5. API成本控制：LLM研判设置单任务50条上限，批量调用控制频率，避免token消耗过快。
6. Worker稳定性：所有任务逻辑加异常捕获，单任务失败不影响整个worker线程和后续任务。
